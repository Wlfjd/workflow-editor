# 기능 명세 (Features)

JIWON's Workflow Editor의 **필수 요구 사항** 충족 여부와, 과제 범위를 넘어 **추가로 구현한 기능** 및 그 **추가 이유**를 정리한 문서입니다.

사용자 관점의 조작 방법은 [README](../README.md#구현-기능)를, 내부 구현·좌표계·히스토리 구조는 [ARCHITECTURE.md](./ARCHITECTURE.md)를 참고하세요.

---

## 1. 필수 요구 사항 (Core Requirements)

과제에서 요구한 핵심 기능과 본 프로젝트의 구현 대응 관계입니다.

### 1.1 노드(Node) 조작

| 요구 사항 | 구현 여부 | 사용 방법 | 구현 위치 |
| --- | --- | --- | --- |
| 캔버스에 새 노드 추가 | ✅ | 툴바 버튼 → 다이얼로그에서 **제목·설명** 입력 후 추가 | `NodeAddDialog.tsx`, `Toolbar.tsx`, `useWorkflow.ts` |
| 드래그로 노드 위치 이동 | ✅ | 노드 본문을 마우스로 드래그. **줌 배율을 보정**해 어떤 확대/축소 상태에서도 커서를 정확히 따라감 | `NodeView.tsx` |
| 노드 선택 후 삭제 | ✅ | 노드 클릭 → `Delete` / `Backspace`, 우상단 `×` 버튼, 툴바 `삭제` 버튼 | `NodeView.tsx`, `App.tsx`, `Toolbar.tsx` |

**구현 요약**

- 노드 위치는 줌/팬과 무관한 **월드 좌표**로 저장합니다.
- 드래그 이동량은 `화면 이동량 ÷ zoom`으로 환산해 저장합니다.
- 노드 삭제 시 해당 노드에 연결된 **엣지도 함께 제거**합니다 (dangling edge 방지).

---

### 1.2 엣지(Edge) 연결

| 요구 사항 | 구현 여부 | 사용 방법 | 구현 위치 |
| --- | --- | --- | --- |
| 노드 간 선(Edge)으로 연결 | ✅ | 포트(●)에서 드래그해 반대편 포트에 드롭 | `Canvas.tsx`, `NodeView.tsx` |
| 출력(Output) → 입력(Input) 방향성 연결 | ✅ | **출력 포트(오른쪽 ●)** → **입력 포트(왼쪽 ●)**. SVG `marker`로 화살표 표시. 입력 포트에서 시작해도 결과는 항상 출력→입력으로 정규화 | `Canvas.tsx` (`resolveDirection`), `EdgeView.tsx`, `utils/graph.ts` |
| (암묵적) 엣지 삭제 | ✅ | 엣지 클릭으로 선택 → `Delete` / 툴바 `삭제` | `EdgeView.tsx`, `App.tsx` |

**구현 요약**

- 엣지는 3차 **베지어 곡선**으로 렌더링합니다.
- 연결 드래그 중 **점선 미리보기 곡선**이 표시됩니다.
- 드롭 확정은 `pointerup` 시점에 `elementsFromPoint`로 재판정해, 빠른 드래그에서도 정확도를 유지합니다.

## 2. 추가 구현 기능 (Beyond Core Requirements)

과제 필수 범위를 넘어, **실사용·편집 경험·데이터 무결성**을 위해 추가한 기능입니다.  
각 항목마다 **무엇을** 추가했는지, **왜** 추가했는지를 함께 기술합니다.

### 2.1 연결 유효성 검증

| 내용 | 상세 |
| --- | --- |
| **기능** | 연결 시 자기 자신 연결 금지, 중복 연결 금지, **사이클 방지(DAG 보장)**, 포트 방향 검사 |
| **사용자 경험** | 규칙 위반 시 하단 **토스트**로 거부 사유 표시. 드래그 중 무효 대상은 **빨간 하이라이트** |
| **추가 이유** | 워크플로우 에디터에서 그래프가 순환하면 실행 순서를 정의할 수 없습니다. DAG를 보장하면 이후 **위상 정렬 기반 실행**으로 자연스럽게 확장할 수 있습니다. 중복·자기 연결은 UI 혼란과 데이터 오류를 유발하므로 사전에 차단했습니다. |
| **구현** | `utils/graph.ts` — `validateConnection`, `createsCycle` (DFS). Vitest 단위 테스트 포함 |

---

### 2.2 연결 드래그 실시간 피드백

| 내용 | 상세 |
| --- | --- |
| **기능** | 연결 드래그 중 반대편 포트 **펄스 애니메이션**, 호버 시 유효(초록)/무효(빨강) 링, 점선 미리보기 곡선 |
| **추가 이유** | 포트가 작아 드롭 위치를 맞추기 어렵습니다. “어디에 연결할 수 있는지”를 **시각적으로 즉시** 알려주면 시행착오와 실패 연결 시도를 줄일 수 있습니다. |
| **구현** | `NodeView.tsx` (포트 CSS 클래스), `Canvas.tsx` (draft 상태·미리보기 path) |

---

### 2.3 캔버스 팬 & 줌

| 내용 | 상세 |
| --- | --- |
| **기능** | 빈 곳 드래그로 화면 이동, 마우스 휠로 **줌-투-커서** (25%~250%), 툴바 줌 버튼·**화면 맞춤(fit view)** |
| **추가 이유** | 노드가 늘어나면 고정 뷰포트로는 작업이 불가능합니다. 팬/줌은 노드·엣지 에디터의 **최소한의 탐색 UX**입니다. 커서 기준 줌은 확대/축소 시 맥락을 잃지 않게 합니다. |
| **구현** | `Canvas.tsx`, `App.tsx` |

---

### 2.4 Undo / Redo

| 내용 | 상세 |
| --- | --- |
| **기능** | `⌘Z` / `⇧⌘Z` (Windows: `Ctrl+Z` / `Ctrl+Y`), 최대 50단계. 노드 **드래그 이동은 종료 시 1회만** 히스토리 기록 |
| **추가 이유** | 그래프 편집은 실수가 잦습니다. 실행 취소 없이는 “한 번 잘못 지우면 끝”이 됩니다. 드래그를 프레임마다 기록하면 undo가 1px 단위로 쪼개지므로, **BEGIN_MOVE / END_MOVE** 패턴으로 히스토리 오염을 방지했습니다. |
| **구현** | `hooks/useWorkflow.ts` — `past / present / future` 히스토리 |

---

### 2.5 노드 추가 다이얼로그 (제목·설명)

| 내용 | 상세 |
| --- | --- |
| **기능** | 노드 추가 시 **제목**·**설명**을 다이얼로그에서 편집 후 확정 (`Enter`/`추가`, `Escape` 취소) |
| **추가 이유** | 타입별 기본 이름만으로는 파이프라인 의미를 표현하기 어렵습니다. 추가 직후 한 번에 라벨과 설명을 정하면 별도 설정 패널 없이도 노드 역할을 명확히 할 수 있습니다. |
| **구현** | `NodeAddDialog.tsx`, `App.tsx`, `types.ts` (`description` 필드) |

---

### 2.6 노드 이름 변경

| 내용 | 상세 |
| --- | --- |
| **기능** | 노드 제목 **더블클릭** → 인라인 편집 (`Enter` 확정, `Escape` 취소, `blur` 시 커밋) |
| **추가 이유** | 추가 후에도 제목만 빠르게 고칠 수 있어야 반복 편집이 수월합니다. |
| **구현** | `NodeView.tsx` |

| 내용 | 상세 |

| **추가 이유** | 브라우저 탭을 닫거나 새로고침해도 작업을 이어갈 수 있게 합니다. |

### 2.8 빈 캔버스 시작

| 내용 | 상세 |

| **추가 이유** | 예제 그래프 없이 사용자가 처음부터 파이프라인을 구성하는 과제 의도에 맞춥니다. |

### 2.9 노드 타입 3종 (입력 / 처리 / 출력)

| 내용 | 상세 |
| --- | --- |
| **기능** | **입력**: 출력 포트만 · **처리**: 입·출력 모두 · **출력**: 입력 포트만. 타입별 색상·설명 표시 |
| **추가 이유** | 모든 노드가 동일하면 “시작→중간→끝” 파이프라인 구조를 사용자가 스스로 기억해야 합니다. 포트 구성을 타입에 묶으면 **잘못된 방향 연결을 UI 단계에서 줄이고**, 워크플로우 의미를 명확히 합니다. |
| **구현** | `constants.ts` — `NODE_KIND_CONFIG` |

## 3. 기능 요약 매트릭스

| 구분 | 기능 |
| --- | --- |
| **필수 — 노드** | 추가, 드래그 이동, 선택·삭제 |
| **필수 — 엣지** | 출력→입력 연결, 방향성(화살표), 선택·삭제 |
| **추가 — 무결성** | 연결 검증(DAG), 중복/자기연결 차단, 삭제 시 엣지 정리 |
| **추가 — 편집 UX** | Undo/Redo, 추가 다이얼로그, 이름 변경, 단축키, 토스트 |
| **추가 — 탐색 UX** | 팬/줌, fit view, 상태바, 빈 캔버스 안내 |
| **추가 — 데이터** | localStorage 자동 저장·복원, 빈 캔버스 시작 |
| **추가 — 모델링** | 노드 타입 3종, 포트 구성 차별화 |
| **추가 — 품질** | 단위 테스트, memo, pointer capture |

## 4. 의도적으로 포함하지 않은 것

현재 범위 밖으로 두었거나, [ARCHITECTURE.md §9](./ARCHITECTURE.md#9-한계와-확장-아이디어)에 확장 아이디어로 적어 둔 항목입니다.

- 멀티 선택, 마퀴 드래그, 그룹 이동
- 노드별 파라미터 설정 패널
- 워크플로우 실행 시뮬레이션
- 미니맵, 스냅 투 그리드, 엣지 라벨
- React Flow 등 외부 그래프 라이브러리 (과제 목적상 직접 구현)

## 5. 빠른 사용 가이드

```
[노드 추가]     툴바 버튼 → 제목·설명 입력
[노드 이동]     노드 드래그
[노드 삭제]     선택 → Delete / × 버튼
[엣지 연결]     출력 포트(●) → 입력 포트(●) 드래그
[엣지 삭제]     엣지 클릭 → Delete
[화면 이동]     캔버스 빈 곳 드래그
[확대/축소]     마우스 휠  또는  툴바 ±
[이름 변경]     노드 제목 더블클릭
[실행 취소]     ⌘Z (Windows: Ctrl+Z)
[연결 취소]     Escape (드래그 중)
```
